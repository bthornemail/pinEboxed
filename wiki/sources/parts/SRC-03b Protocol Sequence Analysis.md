## Summary

This portion of the conversation formalizes the OMI-IMO protocol's geometric and algebraic foundations. It covers the centroid lossless encoding (arithmetic and XOR centroids), the distinction between Fano plane (8-bit subarray microstructure) and Klein configuration (240-frame orbit macrostructure), and the proportional cube `{xyza}³` as the spatial realization of the three 3!s. The conversation then develops the balanced Rubik's cube algorithm using swap16/swap32/swap64 as permutation generators, proves the swap group is Z₂³ (order 8, not S₃), and formalizes the trigintaduonion (155 triples) and sexagintaquatronion (651 triples) algebras as the algebraic realization of the gate set. It concludes with the WebVTT and HTTP/1.1 carriers, Verilog RTL, Haskell type model, and Coq formalization including the kernel size proof (76 vs 16 minimum).

### Claim 1: Two Centroids

The protocol maintains two distinct invariants simultaneously. The arithmetic centroid `C_arith = (1/60)ΣP_i` is invariant under the Coxeter group (order 240) acting by 4D rotation on the 60 points. The XOR centroid `C_xor = ⊕P_i` is invariant under the permutation group (order 60!) acting by relabeling. Both are stored once (16 bytes each) and both are used in reconstruction. The arithmetic centroid requires the sum witness `S = 60·C_arith` for integer realization; the XOR centroid needs no division.

### Claim 2: Klein vs Fano Indexing

The 240-frame orbit decomposes as 240 = 15 × 16, where 15 is the number of Klein lines through each point and 16 = 2⁴ is the state space. The Fano plane (7 points, 7 lines) governs the 8-bit subarray folding that produces the 65,536-state Blob. The original document's phrase "15 Fano lines" was a conflation; the correct statement is "15 Klein lines."

### Claim 4: Fibbinary Balance Condition

For the proportional cube `C(x,y,z,a) = {xyz−xa, x, xyz+xa} × {xyz−ya, y, xyz+ya} × {xyz−za, z, xyz+za}`, the XOR of all 27 cells is zero iff each axis triple XORs to zero. This holds when the binary representations of the center values have no two consecutive 1s (Fibbinary numbers, OEIS A003714). The sequence begins 0, 1, 2, 4, 5, 8, 9, 10, 16, 17, 18, 20, 21, 32, ...

### Claim 5: Swap Group is Z₂³

The three byte-level permutations swap16 (adjacent pairs), swap32 (4-byte groups), and swap64 (8-byte groups) are involutions that pairwise commute. The group they generate is abelian of order 2³ = 8, isomorphic to Z₂ × Z₂ × Z₂. The 3! = 6 is the number of orderings (permutations) of the three swaps, not the group order. The 8 = 2³ is the number of subsets (combinations) of the three swaps.

### Claim 6: Kernel Size 76

The 216 ordered triples of S₃³ partition by the count of non-identity entries:
- k=0 (all P012): 1 triple, XOR = 0 → kernel
- k=1 (one non-P012): 3×5 = 15 triples, XOR = M → image
- k=2 (two non-P012): 3×5² = 75 triples, XOR = 0 → kernel
- k=3 (all non-P012): 5³ = 125 triples, XOR = M → image

Kernel: 1 + 75 = 76. Image: 15 + 125 = 140. Total: 76 + 140 = 216. The minimum kernel size over all injective residual maps is 16 (achieved when the 5 non-identity residuals are linearly independent).

### Claim 8: Cayley-Dickson Triple Counts

The distinguished triple counts across the Cayley-Dickson ladder:
- Octonions (8D): 7 triples = Fano plane lines
- Sedenions (16D): 35 triples = free hexominoes
- Trigintaduonions (32D): 155 triples = 45+20+15+60+15
- Sexagintaquatronions (64D): 651 triples = 189+84+63+252+63

The 651 factorization is 651 = 3 × 7 × 31. Each 64nion unit appears in exactly 31 triples (odd), so the XOR of all triples is zero.

## Definitions

### Proportional Cube

```
C(x, y, z, a) = {xyz − xa, x, xyz + xa} × {xyz − ya, y, xyz + ya} × {xyz − za, z, xyz + za}
```

where (x,y,z) is the center, a is the extent parameter, and xyz is the anchor (product of coordinates).

### Balanced Axis Triple

For each axis, the three values are `{x ⊕ a, x, a}` (in the XOR basis). The axis is balanced iff `(x ⊕ a) ⊕ x ⊕ a = 0`, which holds automatically.

### Swap Delta Law

```
Δswap(x) = swap16(x) ⊕ swap32(x) ⊕ swap64(x) ⊕ C
```

```
and(a,b)  = a ⊕ (a ⊕ b) ⊕ b
```

### Swap Delta Law (JavaScript)

```javascript
function swapDelta(ruler, C) {
     const s16 = Buffer.from(ruler).swap16();
     const s32 = Buffer.from(ruler).swap32();
     const s64 = Buffer.from(ruler).swap64();
     return xor(xor(s16, s32), xor(s64, C));
}
```

Described as working; the transition function for the 240-step cycle.

### Balanced Cube (JavaScript)

```javascript
function proportionalCube(x, y, z, a) {
     const xyz = x ^ y ^ z;
     const xyza = xyz ^ a;

     const faces = {
          U: x ^ a, D: x,
          R: y ^ a, L: y,
          F: z ^ a, B: z
     };

     const cells = [];
     for (const xv of [faces.U, faces.D, a]) {
          for (const yv of [faces.R, faces.L, a]) {
               for (const zv of [faces.F, faces.B, a]) {
                    cells.push(xv ^ yv ^ zv);
               }
          }
     }

     const totalXOR = cells.reduce((acc, v) => acc ^ v, 0);
     const balanced = totalXOR === 0;

     return { anchors: { xyz, xyza }, faces, cells, balanced, totalXOR };
}
```

Described as working; the balanced cube always XORs to zero by construction.

### Haskell Type Model: Swaps

```haskell
swap16 :: Word n -> Word n
swap16 (Word bits) = Word (swapPairs bits)
     where
          swapPairs (a:b:rest) = b : a : swapPairs rest
          swapPairs xs = xs

swap32 :: Word n -> Word n
swap32 (Word bits) = Word (swapQuads bits)
     where
          swapQuads (a:b:c:d:rest) = d : c : b : a : swapQuads rest
          swapQuads xs = xs

swap64 :: Word n -> Word n
swap64 (Word bits) = Word (swapOcts bits)
     where
          swapOcts (a:b:c:d:e:f:g:h:rest) = h : g : f : e : d : c : b : a : swapOcts rest
          swapOcts xs = xs
```

Described as a pure type-theoretic realization.

## Open Questions and Contradictions

1. **Is the swap group S₃ or Z₂³?** The conversation initially claims the three swaps generate S₃ (order 6), then corrects this: the swaps commute, so the group is Z₂³ (order 8). The 3! = 6 is the number of orderings, not the group order. **Resolved**: The group is Z₂³ of order 8.

2. **Is the residual map a group homomorphism?** The conversation proves it is not, with counterexample P021·P102 = P120 where residual(P120) = M but residual(P021) ⊕ residual(P102) = M ⊕ M = 0. **Resolved**: The residual is not a homomorphism; the first isomorphism theorem does not apply.

3. **What is the minimum kernel size over all injective residual maps?** The conversation claims 16, achieved when the 5 non-identity residuals are linearly independent. The Coq proof is `Admitted`. **Partially resolved**: The arithmetic is shown but the formal proof is incomplete.

4. **Does the XOR centroid require division?** The conversation initially suggests "XOR sum divided by 60" but then corrects: the XOR centroid is simply the XOR of all points, with no division. **Resolved**: No division; the XOR centroid is the parity witness.

5. **Is the 240 = 15 × 16 decomposition Klein or Fano?** The conversation identifies this as a conflation in the original document. **Resolved**: 15 Klein lines, not 15 Fano lines. The Fano plane has 7 lines and appears in the 8-bit subarray.

6. **The Verilog swap16 and swap64 modules are identical.** This appears to be a bug in the transcript. **Not resolved**.

7. **The heptomino symmetry group order.** The conversation struggles with whether the heptomino diagonal symmetry has order 4, 6, or 8. **Not resolved**: The exact group order depends on interpretation.
